# Manager operations update (unreleased)

- Manager closing is collapsed by default. Native closing links expand it. Only physical counts and cash are reviewed; no expected balances or discrepancy hints are shown to the manager. The database captures expected balances privately for the owner. Missing expected history or a mismatch no longer blocks submission; valid whole-number counts, authorization and duplicate-submission checks remain.
- Manager → Stock → Staff meals records an active staff member, category and 1–10 pieces per entry. This is not a daily allowance cap. Server-side transactions deduct stock once and retain dated staff/category totals. Uncertain requests retain an idempotency key. Entries require opening stock and reject a closed day. Owner → Reports → Daily profit shows meal entries and totals, and includes ingredient cost separately; staff meals are not sales or wastage.
- Mark all as read persists account-specific read receipts through the highest loaded notification ID. Newer arrivals remain unread. Read history is accessible with Show read.
- Closing reminders use server-generated ten-minute slots relative to the owner's configured closing time. Silence applies to the current slot; the next slot can ring until submission. Owner-recorded leave/off/holiday (including half-day records, since no AM/PM session is captured) suppresses reminders. Prior-day tasks are also suppressed while the current manager is off today. Owner notifications remain informational.

Validation: 44 application tests, 7 dedicated database integration tests, and the web production build passed. Database migration tested locally only. No public deployment, APK release or production stock changes made. Android push behavior needs device testing after the coordinated migration and APK update. Phone notification permission, network access and Android background restrictions still affect delivery.
